# 连续任务与恢复

一个委托对应一个 job。`task_dossier.py` 将原始请求、模型整理的目标、计划、完成条件、主人补充和实际核验证据分别保存；任务状态独立于聊天窗口的最近消息，也不写成人格记忆。模型只能修改计划，不能生成主人授权或伪造工具证据。

在同一对话里补充要求会进入原任务的收件箱。模型推理期间收到新要求，旧动作会被丢弃再规划；已经发出的动作必须如实核对。网页动作 `computer_update` 的 task_note 必须引用主人本轮原句，密码/验证码使用专用私密填写窗。

“继续刚才的任务”使用 `computer_resume`，沿用原 job，不新建一项重复委托。浏览器恢复先读当前页面；普通命令任务若中断结果未知，不自动重跑旧命令，需要另行委托检查当前实际结果。现有桌面接管期间，先交回桌面再续办。

点击等操作回执丢失时，检查点保留待核对状态。引擎在 fresh snapshot 和成功的 browser_check 之前拒绝再次变更页面；未知结果不会被写成已失败或已完成。原始网页和浏览器 profile 留在专用桌面，重启不自动重发注册。

标签页与浏览器应用是不同范围。`browser_tabs`、`browser_close` 只访问本任务拥有的页面；空列表不表示桌面浏览器已关闭。`browser_session_status` 只读检查专用 Chromium 的进程及端口，不启动浏览器。主人明确授权后，`browser_shutdown` 用正常退出流程关闭整个专用浏览器，必须核对进程和端口都已消失；这份应用状态证据可以验证退出，不再要求从已经关闭的网页里查文字。它不会按进程名称强杀其他浏览器，也不会为验证而重新打开窗口。

已中断任务仍可被主人明确取消，取消后不能续办。连续相同错误或重复空观察达到无进展条件时，任务会暂停并保留证据，不反复消耗模型调用；正常交接等待不会被算成失败。主人继续任务时仍需核对未知副作用，关闭浏览器的证据不能证明注册、支付等其他操作是否成功。

私密字段值仍只在 RAM 中。检查点仅保存页面涉及私密输入的标记。服务重启或人工接管后，旧的精确脱敏表无法恢复，因此观察改为受限投影：只报告可识别的流程阶段与固定导航控件，不给模型原始正文、标题、URL 或截图。无法安全识别的页面交给主人通过真实桌面核对；不会为保持自动化而落盘保存密码。

进度查询默认聚焦当前对话关联任务，再选正在执行的任务；只有明确询问任务历史时列出多项。状态区分执行中、等待主人、未知操作待核对、中断与完成，工具结果交给模型结合问题解释，任务原始命令输出不进入无关对话。

遗忘操作更新持久版本，并清理全部相关网页会话中的完成、失败、中断记录及回复/识别缓存；旧推理失去提交资格。保留无正文的请求 tombstone 防重放。任务执行记录、管理员备份和浏览器网站数据是不同数据范围，本功能不声称替代系统级安全擦除。

板端任务 RPC 第 3 版补充 original_request 与持久 note_id。resume_id 是请求去重标识，返回的 job_id 仍是原任务。旧板端需更新固件才能正确接收此恢复协议；原有聊天、状态与提交接口保留兼容。

验证：`python3 -m unittest discover -s computer -p test_full_audit_repairs.py`，包括 30 步以上任务、迟到动作、丢失回执、重启、跨会话遗忘与同任务补充；仍须使用合成网站验证实际浏览器链路，并安排实体设备验收。

## 长任务的工作记忆与验收

执行器共用 `task_runtime.py`。历史不再按 11/17 条截断：达到可配置的字节预算后，保留最近的动作/结果配对，用同一后端模型生成带步骤引用的工作摘要。摘要属于低信任工作笔记，原始请求与主人补充始终独立保留。摘要失败时仍可用 `task_history` 按关键词和步骤游标回查本任务的脱敏记录；不能读取其他任务、私密字段或历史截图。任务证据还保存在追加的 `task_events` 中，绑定任务、步骤、要求版本及证据标识。

计划支持步骤状态、前置步骤与证据引用，完成条件可逐项绑定核验步骤。结构化计划标记完成必须引用当前要求版本的实际成功检查。独立验收可以同时引用操作和历史作为辅助依据，每项结论仍须有当前版本下实际成功的观察或核验；不能凭模型自述生成事实。成功收尾前由当前配置的同一个模型进行独立只读验收，对照原始委托与补充逐项找缺漏；缺项返回执行循环补做，达到配置轮数后暂停。验收模型无法覆盖所有语义错误，也不能推翻取消、未知副作用和权限检查。普通聊天没有增加这一轮验收。

过期元素引用被明确分类为“尚未发送输入”，可重新观察、换定位后继续；传输超时仍按未知效果处理，不因此重放。连续已知错误在硬停止前会提示重新规划，最多四次无进展后暂停。它不保证每个网站都能自动恢复。

`command_start` 返回受管理命令句柄，`command_status` 可等待并核对退出结果。每项任务最多一个此类命令，后代进程仍属于原有 Scope/cgroup，不能脱离任务常驻；取消与服务重启不会重放命令。命令退出后必须重新检查，不能沿用执行期间的核验。GUI 阶段可查看已有句柄，但不能借此启动任意 shell 绕过网站保护。

独立新委托进入有界持久队列，默认最多 8 项、一次只执行一个重任务，聊天可并行。修改/取消原委托仍针对原 job。暂停的桌面任务保留实际页面资源，其他任务不得接走这份页面；需先继续或停止原桌面任务。这样适合有限内存的主机，并不意味着同时运行多个浏览器 Agent。

命令与网页成功收尾均可学习经过核验的通用方法，包含适用条件、避坑与核验方式；失败记录只影响方法评分，不自动替换成功版本，也不赋予权限。默认保留 64 条活跃方法、每任务最多选 4 条，均可配置。

自动回归：`python3 -m unittest discover -s computer -p test_task_runtime.py`。真实浏览器、同模型探针与人工验收应分别记录，不能把模拟模型测试当成真实任务成功率。
