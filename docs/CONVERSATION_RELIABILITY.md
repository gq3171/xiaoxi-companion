# 对话、核验与任务提交

一次对话要经过模型理解、收件确认、动作提交和回复交付。模型回复失败，并不说明电脑执行失败；任务已入队，也不代表已经完成。网页回复的 `failure` 保存阶段、错误类别和效果状态，任务状态仍以任务库为准。错误响应不包含提供商异常正文或密钥。

- `stage=model`：模型调用或输出校验未完成，本轮尚未发起动作。
- `stage=submit`：明确拒绝入队，没有查到本轮任务记录。
- `stage=actions/delivery`：动作或交付回执未完成，必须核对实际结果。
- `effects=not_started`：没有进入动作提交，可由主人新一轮明确要求重试。
- `effects=submitted`：已有持久任务，展示原任务编号与实际状态。
- `effects=check_required`：不能确认效果，不自动重做。

浏览器刷新或同一个消息 ID 重传只查询原结果，不重新推理或执行。主人新发“再试试”时，模型会读到同一个授权网页最近八轮、一天内的收件记录，包括失败请求的原话和状态。这些是短期上下文，不会因为超时就变成主人的长期事实，也不会发送另一个网页会话未被接受的草稿。忘记操作的 epoch 同时约束这份副本与正在进行的推理。服务重启留下的不确定操作仍需先核对。

重试未提交的任务时，任务档案保留原请求及本次重试确认，不能只剩下“再试试”四个字。已有任务或不确定效果的简单重试先读实际状态，避免一个新对话 ID 造成重复执行。取消、换话题和新的明确请求不继承旧重试意图。

主人明确要求使用浏览器或查看官网时，模型应生成真实电脑任务，保留目标、方法和限制。对明确的肯定请求，接口会检查动作是否匹配；不匹配时最多要求模型改写一次，仍不匹配就明确失败，不编造完成结果。不确定的表达、能力询问和否定请求仍由模型结合上下文判断，不直接用关键词生成执行命令。

搜索摘要不等于已打开网页。搜索失败或结果为空时直接说明缺少可核验资料，不再让模型补一篇看似查过的答案。有资料时要求区分摘要与网页、标明支持结论的来源，并检查对象和日期。历史中的主人原话与小溪的回答分别标注：小溪引入的错误型号不能转述成主人提供的信息。涉及购买或兼容性时先确认用途和已有硬件。

这些机制保障上下文、动作和状态的一致性；不能保证模型的每个事实判断都正确。当前资料、硬件兼容性等仍需实际来源支持。

回归入口：

```sh
python3 -m unittest discover -s computer -p test_home_chat.py
python3 -m unittest discover -s computer -p test_dialogue_policy.py
python3 -m unittest discover -s computer -p test_brain.py
```

测试使用临时数据库、合成对话和模拟超时/回执丢失，覆盖重启、隔离、遗忘、原请求归属、重复提交防护和空搜索。真实模型验收也应使用隔离会话和公开测试页面，不把用户正在使用的账号或浏览器拿来做测试。
